# Phone Mirror

Android는 USB 또는 Wi-Fi로, iPhone / iPad는 USB로 연결해 화면을 앱 안에서 보는 한국어 macOS 앱입니다. macOS 14 이상이 필요합니다.

기존 Swift 앱을 유지하면서 Windows/macOS 공통 **Rust + Tauri 앱**을 `desktop`에 추가했습니다. Android USB·Wi-Fi 영상과 캡처·녹화·전체 화면·PiP를 지원하며, Mac USB iPhone 화면 수신도 구현했습니다. iPhone은 보기 전용이며 실기기 없이 모의 검증까지만 완료했습니다. [새 앱 실행·빌드 방법](desktop/README.md)과 [검증 기록](desktop/TESTING.md)을 참고하세요. 이 문서의 아래 내용은 기존 Swift 앱 기준입니다.

## 실행

```sh
open "dist/Phone Mirror.app"
```

Android는 데이터 USB 케이블로 연결한 다음 개발자 옵션의 **USB 디버깅**을 켜고, 폰에서 연결 승인을 허용하세요. 앱에서 기기를 선택하고 **폰 화면 보기**를 누르면 오른쪽에 실제 폰 화면이 표시됩니다.

다른 맥에서는 [Homebrew](https://brew.sh)를 설치하고 다음 명령으로 ADB를 설치합니다. 빌드에는 Xcode 또는 Swift 컴파일러가 포함된 Command Line Tools가 필요합니다.

```sh
bash scripts/install-dependencies.sh
bash scripts/build.sh
open "dist/Phone Mirror.app"
```

## Android Wi-Fi 연결

Android 11 이상에서 폰과 맥을 같은 Wi-Fi에 연결합니다. USB 케이블 없이 최초 페어링할 수 있습니다. 폰의 **개발자 옵션 → 무선 디버깅**을 켜고 필요한 네트워크 승인을 허용하세요.

1. 앱에서 **Wi-Fi 페어링 · 연결**을 엽니다. 화면 보기 중이면 먼저 종료하세요. USB 케이블을 연결해 둔 상태에서도 Wi-Fi를 추가할 수 있습니다.
2. 폰에서 **페어링 코드로 기기 페어링**을 선택합니다.
3. 검색 결과의 **페어링** 행을 선택하거나 폰에 표시된 페어링 IP 주소:포트를 입력합니다.
4. 6자리 코드를 입력하고 **페어링**을 누릅니다. 코드는 명령 인자·앱 설정·연결 로그에 저장하지 않고 프로세스 표준 입력으로 전달한 뒤 화면에서 지웁니다.
5. 같은 기기의 연결 서비스를 찾으면 연결합니다. 자동 연결되지 않으면 폰의 무선 디버깅 기본 화면에 표시된 **연결 IP 주소:포트**를 입력하고 **연결**을 누릅니다. 페어링 포트와 연결 포트는 다릅니다.
6. 창을 닫고 목록에서 **Wi-Fi 연결됨**인 폰을 선택해 **폰 화면 보기**를 누릅니다.

IP 주소는 IPv4 또는 대괄호로 감싼 IPv6 형식이며 포트는 1~65535 범위입니다. 검색되지 않으면 같은 Wi-Fi인지 확인하고 주소를 직접 입력할 수 있습니다. 검색은 ADB의 mDNS를 사용하며, 네트워크가 mDNS를 차단하면 주소 변경 자동 검색이 제한됩니다.

USB와 Wi-Fi 연결을 목록과 영상 헤더에서 구분합니다. 같은 폰이 두 방식으로 연결되어 있으면 별도 항목으로 표시합니다. 영상·소리·조작·스크린샷·녹화는 기존 기능을 사용합니다.

재연결은 기기의 실제 일련번호와 선택한 연결 방식을 기준으로 합니다. 저장한 TLS 서비스 이름을 다시 검색하고, 주소·포트 또는 서비스 이름의 임의 접미사가 바뀌면 새 주소로 연결한 뒤 일련번호를 확인합니다. IP 주소를 다른 폰이 사용해도 재연결 대상으로 바꾸지 않습니다. USB와 Wi-Fi 간 자동 전환도 하지 않으며 직접 기기를 선택하면 이전 재연결을 취소합니다. 페어링 해제, 무선 디버깅 종료, 다른 네트워크 접속 시에는 다시 설정해야 할 수 있습니다.

## 화면과 조작

- Android 영상은 별도 창 없이 앱 안에서 표시됩니다. VideoToolbox로 H.264 영상을 디코딩합니다.
- 화면 안에서 클릭·드래그로 터치와 스와이프를 보냅니다. 검은 여백에서 클릭하면 폰에 입력을 보내지 않습니다.
- **뒤로 / 홈 / 최근 앱** 버튼을 제공합니다. 화면을 클릭해서 키보드 포커스를 둔 뒤 문자, Enter, Backspace, 방향키를 사용할 수 있습니다. 현재 문자 입력은 Android의 키 매핑에 따라 제한되며 한국어 IME 입력은 구현하지 않았습니다.
- 우클릭은 뒤로, 화면에 포커스가 있으면 ⌘F는 전체 화면, ⌘H는 홈입니다.
- 화질·최대 프레임·소리·조작·화면 켜두기는 화면 보기를 종료한 뒤 바꿀 수 있습니다. 실제 수신 fps는 정지 화면에서 낮아질 수 있습니다.
- **앱을 항상 맨 위에** 설정은 연결 중에도 바꿀 수 있습니다.

## 스크린샷

오른쪽 위 **스크린샷** 또는 **⌘⇧S**를 누르고 저장 위치를 선택합니다. 폰 영상의 실제 픽셀 크기로 PNG를 저장합니다. 앱의 버튼이나 검은 여백은 포함하지 않습니다. 스크린샷은 버튼을 누른 시점의 프레임입니다.

## 화면 녹화

1. 오른쪽 위 **녹화** 또는 **⌘R**을 누르고 MP4 저장 위치를 선택합니다.
2. 빨간 녹화 표시와 경과 시간이 나타납니다.
3. **녹화 종료**를 누르면 파일을 마무리하고 저장 결과를 표시합니다.
4. **Finder에서 보기**로 저장된 파일을 찾을 수 있습니다.

MP4는 H.264 영상으로 30fps 녹화합니다. Android 소리가 실제로 수신되고 있으면 AAC 오디오도 함께 저장합니다. 소리가 꺼져 있거나 기기가 소리 캡처를 지원하지 않으면 영상만 녹화합니다. 보호된 콘텐츠나 앱의 정책에 따라 영상·소리 캡처가 제한될 수 있습니다.

정지 화면도 녹화 시간에 맞춰 유지합니다. 폰을 회전하면 미리보기는 새 크기로 표시하고, 녹화 파일은 시작 시 화면 크기를 유지하면서 영상을 맞춰 넣습니다. 화면 보기 종료, 연결 중단, 앱 종료 시 진행 중인 녹화를 마무리합니다. 강제 종료나 전원 손실은 이 저장 절차를 거치지 않습니다.

## 연결 상태

USB 기기 인식과 실제 영상 수신을 구분합니다.

| 표시 | 의미 |
| --- | --- |
| 기기 연결 대기 | 선택할 폰이 없음 |
| 기기 연결됨 · 화면 보기 준비 | USB로 폰을 인식했으며 아직 영상을 시작하지 않음 |
| 디버깅 승인 대기 | 폰에서 맥의 디버깅 연결을 승인해야 함 |
| 영상 연결 중 | 화면 전송을 시작했고 첫 프레임을 기다리는 중 |
| 화면 수신 중 | 실제 영상 프레임을 디코딩해 표시 중 |
| 영상 수신 지연 | 4초 이상 새 프레임이 없어 마지막 수신 화면을 표시 중; 정지 화면도 원인일 수 있음 |
| 자동 재연결 대기 | 같은 폰의 선택된 연결 방식과 승인 상태를 기다리며 재시도 예정 |
| 연결 끊김 / 연결 실패 | USB 장치 또는 영상 채널이 끊겼거나 시작하지 못함 |
| 화면 보기 종료 | 사용자가 화면 보기를 종료함 |

USB 및 연결된 Wi-Fi 장치는 2초마다 확인합니다. 첫 프레임이 15초 동안 도착하지 않거나 영상 채널이 끊기면 **자동 재연결** 설정에 따라 같은 폰에 다시 연결합니다. 재시도 간격은 1·2·4·8·16초이며 연속 5회 실패하면 멈춥니다. 폰이 없거나 승인 대기·오프라인 상태일 때는 시도 횟수를 소모하지 않습니다. 실제 첫 프레임이 도착하면 실패 횟수를 초기화합니다.

**화면 보기 종료**, 기기 변경, 폰 종류 변경은 대기 중인 재연결도 취소합니다. 앱을 실행할 때 저장된 기기를 자동으로 미러링하지 않습니다. 녹화 저장을 마친 뒤 재연결하며 새 연결에서 녹화를 자동 시작하지 않습니다.

## 설정 저장

화질·프레임·소리·조작·화면 켜두기·항상 맨 위·자동 재연결, 폰 종류와 종류별 최근 선택 기기 및 연결 방식, 창 위치와 크기를 UserDefaults에 저장합니다. 앱 재실행 시 복원하며 잘못되거나 손상된 값은 검증 후 기본값으로 복구합니다. 저장 실패는 별도 안내로 표시합니다. 사라진 기기 대신 잠시 다른 기기를 표시하더라도 저장된 선택을 덮어쓰지 않습니다.

## iPhone / iPad

데이터 USB 케이블로 연결하고 잠금을 해제한 뒤 **이 컴퓨터를 신뢰**를 선택하세요. 앱에서 iPhone / iPad를 선택하고 기기가 나타나면 화면 보기를 시작합니다. 필요한 macOS 캡처 권한을 허용하세요.

AVFoundation / CoreMediaIO의 USB 화면 캡처로 앱 안에 표시하며, 같은 PNG·MP4 저장 기능을 사용합니다. 아이폰의 맥 터치 조작과 소리 재생·녹화는 지원하지 않습니다. **현재 아이폰 실기기가 없어 화면 전송과 저장은 실기기 검증하지 못했습니다.**

## 검증

```sh
swift test --build-system native
bash scripts/build.sh
"dist/Phone Mirror.app/Contents/MacOS/PhoneMirror" --self-test
```

Android 실기기를 연결하고 잠금 해제한 상태에서 통합 검증을 실행할 수 있습니다. 지정 폴더에 실제 폰 화면을 포함한 PNG·MP4를 저장하므로 로컬에서만 보관하세요. 기존 GUI 앱은 종료하고 실행합니다.

```sh
"dist/Phone Mirror.app/Contents/MacOS/PhoneMirror" --smoke-test "$PWD/dist/Verification"
```

통합 검증은 앱 모델을 사용해 첫 프레임 수신, PNG 저장, 소리가 준비되면 오디오를 포함한 MP4 녹화, 정상 종료, 영상 소켓 중단 시 녹화 저장, 자동 재연결, 수동 종료 후 자동 재시작 방지, 선택 기기 설정 복원을 확인합니다. 소켓 중단은 테스트에서 실제 영상 채널을 닫는 방식으로 재현하며, 물리적으로 케이블을 뽑는 작업과는 다릅니다.

이 맥의 삼성 SM-S901N (Android 16)에서 앱 내 영상 표시와 886×1920 PNG, H.264/AAC MP4를 확인했습니다. 저장된 정상·연결 중단 녹화 파일을 FFmpeg로 끝까지 디코딩해 검사했습니다. 검증용 미디어는 gitignore에 포함된 `dist/Verification`에 저장합니다.

## 구현과 배포

ADB의 USB 또는 Wi-Fi TLS 연결과 로컬 포워딩으로 scrcpy 5.0 서버의 영상·소리·제어 스트림을 받는 네이티브 Swift 클라이언트입니다. 호환 버전의 서버와 Apache 2.0 라이선스를 앱에 포함했습니다. scrcpy 실행 파일과 FFmpeg는 실행 의존성이 아니며, Android 연결에는 ADB가 필요합니다. 무선 페어링·검색에는 `adb pair` 및 `adb mdns services`를 지원하는 최신 Platform Tools를 사용하세요. 서버 출처와 해시는 `Vendor/README.md`에 기록했습니다.

앱은 로컬 임시 서명한 개발용 빌드입니다. 다른 맥에 배포하기 위한 Developer ID 서명과 공증은 포함하지 않았습니다.

공식 자료: [scrcpy 개발 및 프로토콜 문서](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/develop.md), [Apple USB 화면 캡처 장치](https://developer.apple.com/documentation/coremediaio/kcmiohardwarepropertyallowscreencapturedevices).

## 구조와 TDD

`PhoneMirrorCore`는 기기 식별·목록 파싱, 설정 검증·저장, 무선 주소와 서비스 파싱, 재연결 정책을 담당합니다. `PhoneMirrorApp/Presentation`은 화면 상태와 사용자 행동, `Infrastructure`는 ADB 명령·무선 페어링 및 검색·USB/Wi-Fi 전송·iOS 캡처·영상 및 소리 처리, `Diagnostics`는 실기기 통합 검증을 담당합니다. 화면 모델에 기기 검색·세션 생성·설정 저장·시간을 주입해서 하드웨어 없이도 행동과 시간 경계를 검증합니다.

개발 기준은 `AGENTS.md`, 테스트 범위와 실행 절차는 `docs/TESTING.md`에 기록했습니다.

Wi-Fi 실기기 검증은 다음 명령으로 실행합니다. 출력 미디어는 로컬에만 보관합니다.

```sh
"dist/Phone Mirror.app/Contents/MacOS/PhoneMirror" --smoke-test-wifi "$PWD/dist/Verification/WiFi"
```

같은 폰을 USB에도 연결한 상태에서 `--verify-port-change`를 추가하면 이미 켜진 무선 디버깅을 USB 명령으로 잠시 껐다 켜서 실제 연결 포트 변경을 재현합니다. 변경된 포트에서 새 첫 프레임을 받고 USB 연결이 유지되는지 확인합니다. 시험 종료 시 무선 디버깅은 켜진 상태입니다. 실제 Wi-Fi IP 주소 변경은 자동 테스트에서 검증하며, 시험을 위해 공유기나 네트워크 설정을 바꾸지 않습니다.

공식 무선 연결 자료: [Android ADB Wi-Fi](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi), [ADB Wi-Fi 서비스와 식별 구조](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/dev/adb_wifi.md).

아이폰 Wi-Fi 송출 앱은 [Phone Mirror Sender](ios/README.md)에 있습니다. Rust/Tauri 데스크톱의 Mac·Windows 수신기와 연결하며 기존 macOS Swift 앱과 독립적으로 빌드합니다.
